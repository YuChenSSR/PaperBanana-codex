# README concept overview

## Purpose and scope

Create a welcoming README overview of the **methodology-diagram route**. The main
takeaway is reference-guided planning followed by a bounded render/critique loop.
The complete engineering flow remains in the integration guide and in a
collapsible README section. Do not combine installation, CLI details, manifests,
error paths, and the statistical-plot branch into the hero illustration.

Content follows the original five PaperBanana agents and this fork's Codex
subscription transport. The overview is a conceptual abstraction, not a new
algorithm or a claim of reproduction performance.

## Prompt

Design a new, polished academic-method illustration for the PaperBanana-Codex
README. Reference image 1 supplies the verified workflow content; reference image
2 supplies the visual quality and illustrative spirit. Make a new composition.
This is a concise concept overview of the methodology-diagram route. Keep the
engineering detail in the separate detailed figure, not in this hero.

Use a wide landscape composition, approximately 2.2:1, preferably at least 3000
pixels wide if the native renderer supports it. Pure white outer background.
Two large, softly rounded fields dominate the image: powder blue for planning,
warm apricot for rendering and iterative improvement. Use small cream-yellow and
sage accents on artifacts and accessories. Typography is near-black, clear and
readable, with natural title case, not all caps. Use crisp navy/charcoal arrows,
restrained illustrative shading, and ample whitespace. Avoid nested dashboard
cards, repetitive outlined rectangles, large paragraphs, and a uniform blue/purple
wash. Do not add a top-level title; the README supplies it.

At far left, show a small paper document and a target symbol grouped as the
input, labeled exactly "Method + intent". The main arrow enters the planning
field. Within that blue field, arrange three newly drawn, charming but professional
helper-agent illustrations in a clear left-to-right sequence. Give them a coherent
original visual family, not copies of the reference robots. Label each once:

- "Retriever": scanning a small gallery with a magnifying glass.
- "Planner": sketching a clear layout with a pencil and notepad.
- "Stylist": applying a restrained palette with a brush or palette accessory.

Between Retriever and Planner, show a small fan of miniature diagram/reference
cards labeled "Reference examples". Between Planner and Stylist, show a concise
layout sketch on paper labeled "Figure plan". After Stylist, a clean document
travels along the arrow toward the rendering phase, labeled "Styled description".
These artifacts communicate transformations visually; do not replace them with
additional text-heavy boxes.

Below Retriever, put a small illustrated reference-library cylinder or organized
stack labeled "Reference set", with a thin dashed arrow feeding Retriever. Below
Stylist, a small color/type sample sheet labeled "Style guide" feeds Stylist with
a separate thin dashed arrow. No arrow should suggest the style guide is a data
processing stage or that reference selection occurs after planning.

In the warm apricot field, create an immediately legible loop rather than a long
row of boxes. Place an illustrated "Visualizer" agent with a drawing/display
accessory near the upper-left of that field. The Styled description arrow enters
Visualizer. Visualizer produces a small thumbnail labeled "Draft image" to its
right. An arrow from Draft image goes down to an illustrated "Critic" holding a
review sheet, in the lower-right of the warm field. A broad, clearly directed
curved feedback arrow returns from Critic to Visualizer, labeled
"Refined description". Inside the loop, include the small text
"Up to N rounds". Make every arrow direction unambiguous and avoid crossings.

From the refinement field, draw one clear right-facing exit to a larger, crisp
example illustration thumbnail on a white canvas, labeled "Final illustration".
Use a simple abstract miniature flow diagram with no invented numeric results.
The exit can carry the small label "Accept / round limit" so the picture does not
claim every final regeneration receives an extra approval pass. The output is the
visual destination and should have more presence than any intermediate thumbnail.

At the top of the blue field, use the compact heading "Plan with references".
At the top of the apricot field, use "Render, review, refine". Do not include
installation steps, CLI commands, manifests, API fallback routes, or plot-code
branches inside the main illustration.

Across the bottom, use one slim, visually quiet support ribbon rather than a
third giant panel. Label it "Codex subscription" with the subtitle
"Text / vision + native image generation". A small terminal-style entry chip
may say "$paperbanana". This is a shared runtime supporting both phases; it is
not a sixth Agent or a new step in the main flow. Do not add token, key, security,
or implementation prose to this ribbon.

Keep exactly the five named Agent roles: Retriever, Planner, Stylist, Visualizer,
Critic. Keep all listed labels spelled correctly. Give each icon an obvious
semantic role and allow the shapes and artifacts to provide visual rhythm.
Prioritize readability at GitHub README width. No fake benchmark values, numerical
quality scores, extra modules, logos, or decorative mascot outside the method.
